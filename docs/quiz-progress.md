# 파트별 퀴즈 이어 풀기

진행 상태는 기존 Supabase 익명 사용자 ID와 퀴즈 파트 키로 구분합니다. 답을 처음 고르거나 ‘처음부터 풀기’를 선택할 때 응시 ID를 만들고, 이어 풀기에서는 같은 ID와 최초 방문 ID를 유지합니다.

## 동작

- 답 선택·제출·다음 문제 이동마다 즉시 브라우저 localStorage와 탭 sessionStorage에 저장한 후 기존 추적기의 내구성 있는 전송 대기열에 넣습니다. 페이지 종료 이벤트에 의존하지 않습니다.
- 파트별로 현재 응시를 보관합니다. 다른 주제, 카드뉴스, 사무실로 이동해도 덮어쓰지 않습니다. 사무실 퀴즈 팝업을 다시 열 때에는 출처와 부모 창을 검증한 메시지로 복원 선택 화면을 엽니다.
- 미완료 풀이로 돌아오면 ‘이전에 풀던 퀴즈가 있어요’, ‘이어 풀기’, ‘처음부터 풀기’를 표시합니다. 이어 풀기는 현재 위치·선택 답·제출 여부·해설을 복원하며, 제출한 답은 입력을 잠급니다.
- 처음부터 풀면 기존 응시를 로컬 보관함과 `lt_quiz_progress.status='abandoned'`로 남기고 다른 응시 ID로 시작합니다. 이미 최종 답안을 제출해 DB상 완료된 응시는 완료 기록을 보존합니다.
- 응시 ID, 퀴즈 UUID·revision, 순서가 고정된 문제 UUID·revision, 복습 구성·원본 응시, 현재 위치, 선택 중인 답, 제출 답·정오답 결과를 저장합니다. 해설은 같은 불변 문제 버전의 원문으로 복원합니다.
- 공개된 최신 퀴즈의 UUID·revision·문제 순서·문제 revision이 다르거나 저장 내용의 일관성을 확인할 수 없으면 이어 풀기를 허용하지 않고 이유와 새 시작을 안내합니다. 이전 기록은 삭제하지 않습니다.
- 미제출 선택은 진행 상태에만 저장하며 공식 답안·점수로 취급하지 않습니다. 공식 채점은 기존 `lt_ingest`가 처리하고, 진행 상태의 제출 답안·정오답·점수는 DB 기록으로 정규화합니다.
- 미완료·중단 응시는 기존 `completed=false`를 유지하므로 완료 기록이나 최종 점수 비교에 포함되지 않습니다. 완료 집계의 시점은 기존과 같이 마지막 답안 제출 시점입니다.

## 동기화·오프라인

기존 15초 주기·인터넷 복구·창 복귀 자동 재전송을 재사용합니다. 제출된 답의 원본 ID와 같은 응시 ID를 유지하고, DB에서 처음 제출한 답을 변경할 수 없도록 검사합니다. 로컬 저장 직후 대기열 기록 전에 종료된 경우에도, 이어 풀기에서 제출된 답을 순서대로 재전송하여 복구합니다. 동일 답안·완료 재전송은 점수를 늘리지 않습니다.

Supabase에서 진행 상태를 읽을 때는 같은 익명 사용자 기록만 가져옵니다. 아직 전송할 로컬 변경이 남아 있는 응시는 오래된 서버 상태로 덮어쓰지 않습니다. 로컬에서 중단한 응시도 다시 활성화하지 않습니다. 서버는 오래된 진행 스냅샷이 최신 위치·제출 상태를 뒤로 돌리지 못하도록 검사합니다.

공개 문제 카탈로그와 마지막 확인된 익명 ID를 캐시해, 이미 로드된 앱에서 Supabase 연결이 끊겨도 로컬 풀이를 복원합니다. 최초 방문은 연결이 필요하고, 사이트 페이지 자체를 완전히 오프라인에서 새로 내려받는 PWA 기능은 제공하지 않습니다. 브라우저 저장을 사용할 수 없으면 저장 범위·실패 안내를 표시합니다. 브라우저 데이터 삭제·시크릿 모드 종료·기기 변경 시 익명 식별이 연결되지 않을 수 있으며, 별도 로그인 없는 다른 기기 이어 풀기를 보장하지 않습니다.

## Supabase

기존 세 마이그레이션 다음에 `supabase/migrations/202610200002_quiz_progress.sql`을 한 번 적용합니다. 기존 데이터·이벤트·답안·점수를 삭제하지 않습니다. 이미 실행한 SQL을 반복 실행하지 마세요.

- `lt_quiz_progress`: 응시별 진행 상태·순번·중단 시점·스냅샷. RLS로 본인만 조회하며 클라이언트의 직접 쓰기는 금지합니다.
- `lt_save_progress`: Auth 사용자·응시 소유권·버전·문제 구성·선택 범위·제출 잠금을 서버에서 검증합니다.
- `lt_abandon_progress`: 본인 응시만 중단 처리하고, 이후 제출을 거절합니다.
- `lt_resume_progress`: 본인 파트별 최신 기록만 반환합니다. 운영자도 이 사용자용 함수로 타인의 임시 선택을 조회하지 못합니다.
- `lt_progress_version`: 버전 1. 기존 `lt_learning_version=3`은 유지합니다.

새 SQL이 없으면 진행 상태 전송을 대기열에 남기면서 명확한 설정 안내를 표시합니다. 이 대기 때문에 기존 공식 답안 전송이 막히지 않도록 처리했습니다. SQL 적용 후 자동 재전송합니다.

현재 응시와 과거 실패 안내를 분리합니다. 현재 진행 상태가 서버에서 확인된 경우에만 현재 응시를 저장 완료로 표시하며, 다른 응시에서 거절된 요청은 ‘이전 기록’으로 따로 표시합니다. ‘저장 실패 내역 보기’에서 요청 종류와 실제 서버 거절 이유를 확인할 수 있습니다. 같은 응시·문제·동일 답안이 저장됐다는 서버 응답이 있으면 해당 과거 실패를 해결 보관함으로 옮기고, 다른 답안에 대한 실제 실패는 숨기지 않습니다. 방문별 전송 순번도 localStorage에 유지해 브라우저 재접속 후의 새 상태가 오래된 순번으로 무시되지 않도록 합니다.

## 검증

실제 공개 49문항 카탈로그를 사용한 브라우저 저장소·전송기 테스트에서 파트 전환, 카드뉴스·사무실 이동에 해당하는 화면 재진입, 새로고침, 탭 저장소가 없는 브라우저 재접속, 네트워크 단절·재연결, 사용자 ID 변경, 버전 변경, 중단 후 새 응시와 로컬 저장/대기열 기록 사이 종료를 검사합니다.

PostgreSQL 테스트에서는 실제 마이그레이션을 실행하고 사용자 간 접근 차단, 미제출 선택과 공식 답안 분리, DB 채점 사용, 제출 답 변경 차단, 오래된 스냅샷·반복 제출·완료의 중복 방지, 중단 기록 보존, 미완료의 비교 제외를 검증합니다. 운영 Supabase에서는 확인용 익명 Auth 세션으로 버전 1과 본인 진행 상태 조회 권한을 확인했습니다. 운영 DB에 검증용 퀴즈 답안·점수는 생성하지 않았습니다.

현재 UI 자동화에 연결된 브라우저가 없어 실제 브라우저에서 클릭하며 이동하는 검증은 수행하지 못했습니다. 이동·재진입은 동일 저장소를 유지하고 화면/탭 저장소를 재생성하는 테스트로 검증했습니다.
