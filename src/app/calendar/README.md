# 취업규칙 스티커 달력

- 브랜치: `feature/calendar`
- 실행: 프로젝트 루트에서 `npm run dev`, `/calendar` 접속
- 기존 홈과 `public/learning`, `team-handoff` 파일은 수정하지 않았습니다.

## 파일

- `page.tsx`: 주제 전환, 상황 팝업, OX 퀴즈, 키보드/포커스 처리
- `data.ts`: 일반 근로자용 표준안에 근거한 9개 대표 학습 상황과 퀴즈
- `calendar.css`: 탁상달력, 스프링, 남색 받침, 스티커, 반응형, 장 넘김 효과
- `public/calendar/assets/*.svg`: 자체 제작한 9개 SVG 스티커
- `public/calendar/source.pdf`: 제공된 2026. 2. 표준취업규칙 원문
- `scripts/calendar-assets.py`: SVG 생성 스크립트. PDF 복사는 최초 제공 파일이 Desktop에 있을 때 실행됩니다.

## 콘텐츠 범위

첫 버전은 주40시간 제조업을 가정한 일반 근로자용 표준안을 사용합니다. 240여 쪽 전체의 모든 조항을 대체하는 것이 아니라, 근로시간·휴일휴가·퇴직해고의 대표 상황을 요약하고 관련 조항과 PDF 파일 페이지로 연결합니다. 단시간근로자용 표준안은 별도이며 원문으로 안내합니다.

법정 기준과 회사 설정 사항을 각각 표시합니다. PDF의 `[선택]`은 취업규칙에 기재하는지의 구분일 수 있어, 법정 의무 면제로 표현하지 않습니다. 달력 숫자는 실제 근무·휴가·퇴직 일정이 아닙니다. 문서는 2026년 2월 배포 기준이며 회사 적용 시 이후 법령 개정과 실제 취업규칙을 확인해야 합니다.

## 확인 결과

2026-10-12: `/calendar`, 원문 PDF, SVG HTTP 200. 페이지 파일 ESLint 및 별도 TypeScript 검사 통과. Headless Edge에서 3개 탭, 9개 안내 팝업, Escape와 닫기, 주제별 3문제 퀴즈 및 결과, 390px 모바일 가로 넘침과 팝업, 브라우저 런타임 오류 부재 확인. 데스크톱·모바일 스크린샷 시각 확인.

프로젝트 전체 TypeScript 검사는 기존 인수인계 폴더의 `@/lib/manual-conversion` 참조와 기존 `.next/types`의 없는 API 경로 참조 때문에 초기 실패했습니다. 해당 기존 파일과 설정은 변경하지 않았으며, 전체 프로덕션 빌드는 검증 완료로 간주하지 않습니다.

Next.js 개발 서버가 루트의 `AGENTS.md`, `CLAUDE.md`를 자동 생성합니다. PDF 추출·브라우저 확인의 임시 도구는 `.tools/`로 격리하고 Git에서 제외합니다. GitHub 업로드·커밋은 하지 않았습니다.
