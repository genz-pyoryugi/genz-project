# 캘린더 OX 퀴즈 연결

## 현재 상태

기존 9문제의 실제 Supabase 저장·조회는 검증했습니다. PDF 원문에 근거한 27문제를 추가해 총 36문제(유형별 12문제)로 확장했습니다.
매 응시에서 3문제를 무작위로 뽑고, 같은 탭의 직전 응시에서 나온 문제는 가능한 한 제외합니다.
실시간 AI 생성 대신 원문 조항·페이지와 해설을 확인한 문제은행을 사용합니다.

### 기존 사용자의 문제은행 업데이트

SQL Editor에서 **`update-calendar-quiz.sql`만 실행**합니다.
기존 문제와 응시 기록은 유지하면서 27문제를 추가하고, 무작위 3문제 출제 및 1~3문제 오답 복습을 저장하는 채점 함수로 교체합니다.
직전 문제은행 업데이트 SQL을 이미 적용했어도 이 통합 업데이트를 실행하면 됩니다.
재실행해도 기존 문제 수정 내용과 응시 기록은 덮어쓰지 않습니다. 기존 DB에서 `setup-calendar-quiz.sql`을 재실행하지 마세요.
로컬 파일 준비만으로 원격 DB가 업데이트되지는 않습니다. 위 SQL을 적용하기 전에는 기존 온라인 문제 3개가 계속 사용됩니다.
적용 후 페이지를 새로고침하고, 새 응시·다시 풀기·기록 조회를 확인합니다.

## 적용 순서

1. **기존 퀴즈 브랜치와 같은 Supabase 프로젝트인지 확인**합니다. 기존 테이블은 수정하지 않습니다.
2. 새 DB에서는 SQL Editor에서 `setup-calendar-quiz.sql`을 한 번 실행합니다. 테이블·접근 정책·채점 함수와 36문제를 하나의 트랜잭션으로 생성합니다.
3. 기존 DB에서는 위의 문제은행 업데이트 SQL만 실행합니다.
4. 프로젝트 루트의 `.env.local`에 아래 두 변수를 실제 값으로 설정합니다.
   - `NEXT_PUBLIC_SUPABASE_URL`: Project URL
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: publishable key (기존 프로젝트의 anon key도 가능)
   - **secret key, service_role key, DB 비밀번호는 NEXT_PUBLIC 변수에 넣지 않습니다.**
5. Auth 설정에서 **Allow anonymous sign-ins**를 활성화합니다. 기존 퀴즈와 같은 프로젝트에서 이미 활성화했다면 그대로 사용합니다.
6. 개발 서버를 재시작합니다 (`npm run dev`). 페이지에서 자동으로 기존 세션을 확인하고, 세션이 없을 때만 `signInAnonymously()`로 익명 사용자를 생성합니다.
   익명 로그인에 CAPTCHA를 설정한 프로젝트라면 CAPTCHA 연동도 별도로 필요합니다. 실패 시 저장 성공으로 표시하지 않습니다.

## 저장 구조

- `calendar_quiz_questions`: 문제, 정답, 해설, 출처, 장, 순서, 버전. 누구나 활성 문제를 읽을 수 있고 일반 사용자는 수정할 수 없습니다.
- `calendar_quiz_attempts`: 인증된 사용자 ID, 제출 답안, 당시 문제·정답·해설, 점수, 총 문제 수, 완료 시각.
- `submit_calendar_quiz`: 로그인 사용자 ID를 인증 세션에서 가져오고 점수를 DB에서 계산합니다.
  클라이언트가 점수나 다른 사용자 ID를 지정할 수 없습니다.
- RLS와 권한으로 본인 기록만 조회할 수 있습니다. 브라우저에서 기록 테이블로 직접 삽입·수정·삭제할 수 없습니다.
- 같은 시도의 저장 재시도는 동일 UUID를 사용하므로 중복 기록이 생기지 않습니다.
- 출제 이후 문제 버전이 바뀌면 저장을 거절하며 다시 풀도록 안내합니다.

## 화면 동작

- 하단 이전·다음 버튼으로 문제를 이동합니다. 미답변 문제에서는 다음 이동이 잠기고, 마지막 문제는 결과 보기로 바뀝니다.
- 이전 문제의 답·정오답·해설은 유지되며 제출한 답은 바꿀 수 없습니다. 미션 게이지는 답변 완료 수만 표시하며 이동 기능이 없습니다.
- 결과의 **다시 풀기**는 직전 응시의 오답만 출제합니다. 전부 맞힌 경우 비활성화됩니다. **새로 풀기**는 직전 일반 응시의 문제를 가능한 한 제외한 다른 3문제를 출제합니다.
- 온라인 오답 복습은 직전 응시 저장 성공 후 시작합니다. 복습도 새 ID로 저장하고 `retry_of`에 원래 응시 ID를 연결합니다. DB에서 해당 사용자의 이전 오답 목록과 일치하는지 검증합니다. 기존 점수·답안은 수정하지 않습니다.
- 문제 이동으로는 저장하지 않습니다. 모든 답변을 완료한 뒤 결과 보기에서 응시 전체를 저장합니다.
- 저장 재시도는 같은 응시 ID를 사용합니다. 다시 풀기는 새 ID로 시작하며 이전 기록을 수정하거나 삭제하지 않습니다.
- 이메일 입력 없이 자동 익명 로그인합니다. 기존 로그인 세션이 있으면 계정을 새로 만들지 않고 재사용합니다.
- 같은 Supabase 프로젝트·같은 브라우저 origin·기본 세션 저장 설정을 사용하면 기존 퀴즈 세션도 재사용합니다.
  서로 다른 포트/도메인 또는 기존 퀴즈의 별도 storageKey 사용 여부는 해당 브랜치 확인이 필요합니다.
- 브라우저 데이터를 삭제하거나 시크릿 창·다른 기기에서 접속하면 기존 익명 사용자 기록을 이어볼 수 없습니다.
- 익명 로그인에 실패하면 재연결할 수 있고, 퀴즈는 기록을 저장하지 않는 연습으로 진행할 수 있습니다.
- 연결값 누락, 테이블 미생성, 네트워크 오류 시 기존 파일의 문제로 **연습 모드**를 제공합니다.
  연습 결과를 온라인 기록으로 저장하지 않습니다.
- 완료한 답안을 저장하지 못하면 결과 화면에서 재시도할 수 있습니다. 저장 전에 페이지를 새로고침하거나 팝업을 닫으면 재시도할 수 없으므로 결과 화면에서 저장 성공을 확인합니다.
- 로그인한 사용자는 최근 20회 기록과 각 답안·해설을 조회할 수 있습니다.
- PDF, 스티커 안내 문구, 이미지는 기존 로컬 파일을 유지합니다. 이번 연결 범위는 OX 문제와 풀이 기록입니다.

## 검증

타입 검사: `npx tsc --noEmit`

Lint: `npx eslint src/app/calendar/page.tsx src/app/calendar/quiz-account.tsx src/app/calendar/quiz-store.ts src/lib/calendar-supabase.ts`

Seed 재생성: `node scripts/seed-calendar-quiz.mjs` (SQL 파일 생성만 하며 DB에 쓰지 않음)

문제은행 SQL 재생성: `node scripts/build-calendar-quiz-bank.mjs` (`quiz-bank.json`의 27문제와 기존 9문제로 업데이트/초기 설정 파일 생성, 원격 DB 쓰기 없음)

원격 적용 후에는 두 사용자로 각각 로그인해 본인 기록만 보이는지, 점수와 답안이 정확한지,
저장 재시도가 중복을 만들지 않는지, 로그아웃 후 비공개 기록이 사라지는지 확인합니다.

로컬 PGlite 검증(`node .tools/quiz-db-tests/test.mjs`)에서 테이블 생성, seed 9문제 및 재실행,
비로그인 접근 제한, 사용자별 RLS, 직접 쓰기 차단, 전부 정답/오답 채점, 답안 스냅샷,
중복 재시도, 누락·중복·다른 장·잘못된 형식·이전 버전 제출 거절을 확인했습니다.
임시 도구는 `.tools/`에 격리되어 있습니다. 이 결과는 원격 익명 로그인이나 원격 DB 연결 성공을 뜻하지 않습니다.

공식 참고: https://supabase.com/docs/guides/database/postgres/row-level-security
